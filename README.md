# DocVault — GitHubをバックエンドにしたNotion風ドキュメント管理Webアプリ

サーバー・DB・認証基盤を一切持たず、**GitHubリポジトリを唯一のデータストア**とする、
チーム（〜20人）向けの構造化ドキュメント管理ツール。
Obsidianの「1 vault = 1リポジトリ」に相当する単一リポジトリ選択方式で動作します。

**最重要の設計原則**: このツールをやめても、中身はGitHub上・Obsidian等でそのまま読める状態を維持する。

- ドキュメントの実体は **YAMLフロントマター付きMarkdown**（独自ブロックJSONなし）
- 画像は `_assets/` に独立バイナリとして保存し、本文から**相対パス**で参照（Base64埋め込みなし）
- ドキュメント間リンクは**通常の相対Markdownリンク**（GitHub上でもクリック可能）
- Alerts・MermaidはGitHubがネイティブ描画する記法をそのまま使用

## 構成（pnpmモノレポ）

```
packages/core   # 純粋ロジック: GitHub APIクライアント / frontmatter / ドキュメント名 /
                # Alerts / 本文セグメント分割 / 見出し抽出 / リンク書き換え /
                # ブロックID / 未参照画像検出 / パス解決（vitestユニットテスト付き）
apps/web        # Next.js (App Router, 静的エクスポート) + React + Tailwind のUI
```

```bash
pnpm install
pnpm dev      # http://localhost:3000
pnpm build    # apps/web/out/ に静的サイトを出力（任意の静的ホスティングに配置可能）
pnpm test     # coreのユニットテスト
```

## 起動フロー

1. アプリを開く → **fine-grained PAT** を貼り付け（localStorageにのみ保存。OAuth不使用）
   - 必要権限: 対象リポジトリの **Contents: Read and write**（Metadata: Read-onlyは自動付与）
2. ドキュメント用リポジトリを1つ選択（vault選択。サイドバーからいつでも切り替え可能）
3. Notion風UIで閲覧・編集。全機能は選択中の1リポジトリ内で完結

共有リンクを開いたユーザーがPAT未登録の場合は、PAT発行を案内する画面を挟んでから
同じドキュメントに到達します（サーバーレス構成上の自然な仕様）。

## 主な機能

| 機能 | 実装 |
| --- | --- |
| ライブエディタ | 編集モード / 閲覧モードの切り替えはない。Milkdown Crepe（ProseMirror + remark）の1画面で完結し、Mermaidと埋め込みは**カーソルが入っていない間だけ描画結果**に差し替わる（Obsidian の Live Preview 相当）。保存されるのは常にプレーンなGFM |
| GitHub Alerts | 5種（Note / Tip / Important / Warning / Caution）。**編集中も色付きで表示**され、`/` やブロックハンドルの ＋ から挿入できる |
| ドキュメントツリー | 任意階層に新規作成。表示名はファイル名（拡張子なし）。フォルダ作成対応（Gitの制約上 `.gitkeep` で空フォルダを表現） |
| 名前の変更 | ページ上部のタイトル欄（Notion風）／ツリーの鉛筆アイコン・ダブルクリック／移動ダイアログのいずれからでもリネーム可能。**ファイル名がドキュメント名そのもの**で、参照リンクは自動更新 |
| 移動 | 移動ダイアログ + ツリーへの**ドラッグ&ドロップ**。参照元全ファイルの相対リンクと、移動したファイル自身の相対リンク・**画像相対パス**を自動で再計算し、**1コミット**で反映 |
| 共有リンク | `?repo={owner}/{repo}&doc={id}`。frontmatterのIDに紐づくため**ファイルを移動しても同じリンクで到達** |
| GitHubで開く | ドキュメントメニューから、開いているファイルのGitHubページ（`blob/{default branch}/{path}`）を新規タブで開く |

| 表示設定 | コードブロックの**折り返し**と、本文の**全幅表示**。アプリ全体の設定としてlocalStorageに保存する |
| コードのコピー | コードブロックのコピーボタンが押した直後だけ「コピー」→「✓」に変わる（画面下部の通知は出さない） |
| ID採番 | 遅延方式。開いた/編集したときに `nanoid`（36^14）で採番しfrontmatterへ書き込み |
| データベースビュー | 全ファイルのfrontmatterを横断集計してテーブル（ソート可）/ カンバン（任意プロパティでグループ化） |
| 検索 | MiniSearchによるクライアントサイド全文検索。pull済みキャッシュから構築（Code Search API不使用） |
| テンプレート | `_templates/*.md` に保存（リポジトリ内なので他ツールからも見える）。`{{title}}` `{{date}}` プレースホルダ対応 |
| 埋め込みブロック | Obsidian互換 `![[file.md#^block-id]]`。編集画面上でそのまま実体を参照表示し、**その場編集で元ファイルへ書き戻し**（Notionの同期ブロック相当。書き戻しは本アプリ独自機能） |
| 未参照画像の削除 | 本文Markdown画像・リンク・埋め込み・**frontmatter内画像（cover等、ネスト含む）**を走査し、候補一覧を提示→ユーザー確認後に削除。削除候補は**アップロード先の `_assets/` 配下だけ**に限定（手動で他の場所に置いた画像は誤削除しない） |

| サイドバー | 開閉可能。状態はlocalStorageに保存され次回も維持される |
| テーマ | ダーク/ライト切り替え（エディタ・Mermaid・コードブロックにも反映） |

## 同期エンジンの設計

読み書きはすべて **Git Data API** に統一しています。

- **pull**: `GET git/ref/heads/main` でHEADのSHAを確認し、**変化があった場合のみ** treeを再帰取得。
  blob SHAが変わったMarkdownだけをblob APIで差分取得（毎分の全ファイル取得はしない）
- **push**: dirtyな全ファイルを blob作成 → tree作成 → commit作成 → `PATCH git/refs`（force: false）
  の1コミットにまとめる。refが進んでいた場合は422で弾かれる（= 競合検知）ため、
  pullして自動リベース。**同一ファイルが両側で変更されていたときだけ**競合ダイアログを表示
- **サイズ制限**: blob APIは100MBまで扱えるため、Contents APIの約1MB制限を受けない。
  画像アップロードもblob経由で同じコミットフローに乗る
- プライベートリポジトリの画像は blob APIで取得して objectURL 化して表示（PATだけで表示可能）
- **偽競合の防止**: GitHub APIのGETは `Cache-Control: max-age=60` を返すため、
  ブラウザHTTPキャッシュに乗ると自分のpush直後に古いrefが見えて偽の競合になる →
  全リクエストを `cache: "no-store"` で素通しする。また、pull/push/移動/削除の
  書き込み操作は内部キューで直列化し、自分のコミット同士のref衝突を防ぐ。
  pull中のキー入力はpull完了時点の最新stateへマージし、編集の巻き戻りを防ぐ

## 検討事項への回答

### 編集モードと閲覧モードを分けない（ライブエディタ）

**モード切り替えは廃止し、Milkdown Crepe の1画面だけにしています。**
Crepeはもともと見出し・リスト・表・画像・GitHub Alertsを編集中もそのまま描画するので、
閲覧モードでしか描画できていなかったのは **Mermaid と埋め込み（`![[...]]`）の2つだけ** でした。
この2つを次のように「カーソルが入っていないときは描画結果、入っているときはMarkdownソース」に
切り替えることで、モードを持つ理由がなくなります（`apps/web/lib/liveEditor.tsx`）。

- **Mermaid**: 図の描画自体は Milkdown のコードブロックが持つ `renderPreview` に載せている
  （プレビューパネルはDOMPurifyでSVGを検証したうえで差し込むので、独自のsanitizeは不要）。
  プラグイン側は「図とソースのどちらを見せるか」のクラス付けだけを担当する。
  図をクリックしたときにソースへ入れるよう、ProseMirror上の位置を `data-dv-pos` としてDOMに持たせている
  （Milkdownのコードブロックは nodeView の `stopEvent` が常にtrueで、クリックがProseMirrorに届かないため）
- **埋め込み**: `![[...]]` だけの段落をウィジェットDecorationで置き換え、参照先の内容を描画する。
  記法そのものを直したいときのために、ウィジェット右上に「ソース」ボタンを置いてカーソルを送り込む。
  ウィジェットの `toDOM` はモジュールレベルの固定関数にしている
  （毎回クロージャを作るとProseMirrorが別物と判断し、1打鍵ごとにReactツリーが作り直される）
- **Alerts**: 引用ブロックのマーカー行を、非編集時はアイコン＋ラベルに見せ替える（下記）
- **相対リンク**: 閲覧モードが持っていた「クリックでアプリ内移動」はエディタ側のプラグインへ移した

Crepeが本文に当てている既定スタイルのうち、ライブエディタとして見たときに不都合なものは
`globals.css` で上書きしています（`.docvault-editor` を1段かぶせて詳細度で勝たせる）。

- `.milkdown .ProseMirror` の `padding: 60px 120px` を外す。
  これが無いと本文だけがタイトル・プロパティ欄より内側に寄って見える。
  代わりに、ブロックハンドル（⠿ / ＋）が本文の左外に出るぶんの余白をページ側（`.dv-doc`）に持たせている
- 画像の `object-fit: cover; min-height: 100px` を `contain` / `auto` にする。
  既定のままだと横長の画像が高さ100pxに切り取られる

閲覧描画（`ReadView`）自体は残っていて、埋め込みブロックが参照先を見せるときに使われます。

### 表示設定（折り返し・全幅）をどこに持つか

**アプリ全体の設定としてlocalStorageに持ちます**（`apps/web/lib/display.ts`）。
Notionのようにページ単位にするならfrontmatterに書くことになりますが、
それは「このツールをやめても中身がGitHub上・Obsidian等でそのまま読める」という原則に反します
（他ツールでは意味を持たない表示都合のプロパティが本文に混ざり、DBビューの列にも出てしまう）。

反映はhtml要素のクラス（`dv-code-wrap` / `dv-full-width`）で行い、
エディタ・埋め込み内の閲覧描画・prose幅が同じCSSルールを共有します。
ただしコードの折り返しだけは、CodeMirrorが行の高さを実測する都合でCSSではなく
`EditorView.lineWrapping` 拡張で行うため、切り替え時はエディタを作り直します（Reactのkey）。

### ドキュメント名はファイル名か、frontmatterの `title` か

**ファイル名に一本化しています。** frontmatterに名前は持たせません。

理由は本アプリの最重要原則そのもので、「このツールをやめても中身がGitHub上・Obsidian等で
そのまま読める」状態にしたときに**名前として見えるのはファイル名だけ**だからです。
GitHubのファイルブラウザにもObsidianのファイルリストにも `title` は出てきません。
名前が2箇所にあると必ずズレるうえ、「`title` を変えたのに表示が変わらない」という形で
どちらが本物か分からなくなります。

したがって:

- **サイドバー / 検索結果 / データベースビューの「名前」列は、すべてファイル名（拡張子なし）**
- 新規作成時に書き込むfrontmatterは共有リンク用の `id` だけ。`title` も本文先頭のH1も作らない
- リネームは3経路（ページ上部のタイトル欄・ツリーの鉛筆/ダブルクリック・移動ダイアログ）から可能で、
  すべて同じ `moveDoc` に集約される → 参照リンクの書き換えと1コミット反映が常に働く。
  リネームが書き換えるのは**ファイルパスと相対リンクだけ**で、本文には手を入れない
- frontmatterに `title` を書けば普通のユーザープロパティとして扱われ、
  データベースビューの列にもなる（ただし表示名としては使われない）

### GitHub Alerts の扱い

Alertsの実体は「先頭行が `[!NOTE]` の引用ブロック」というプレーンなMarkdownなので、
**独自ノードは一切追加していません**（追加するとGitHub上での見え方と乖離するため）。

- **挿入**: Crepeのスラッシュメニュー（`/` およびブロックハンドルの ＋）に "Alert" グループを追加する
  だけで、Code / Table などと同じ導線に乗せている（専用ツールバーは置かない）。
  項目ラベルは `Note 補足` のように併記してあるので `/note` でも `/補足` でも引ける
- **表示**: ProseMirrorのDecorationで、条件を満たす引用ブロックに色と枠を与える。
  マーカー（`[!NOTE]`）はMarkdownの実体なのでDOMからは消さず、カーソルが入っていない間だけ
  CSSでGitHubと同じ「アイコン＋ラベル」に見せ替える（Mermaid・埋め込みと同じ考え方）。
  カーソルを置くとマーカーの実体が出るので、そのまま編集・削除できる
- **閲覧描画（埋め込みの参照表示）**: GitHubと同じラベル・アイコン・配色で描画
  （`packages/core/src/segments.ts`）。リスト内にインデントされたAlert、
  複数段落・リストを含むAlertにも対応
- **保存**: remark-stringifyは `[` を `\[` にエスケープし、段落区切りに `>` だけの空行を挟むため、
  保存前に GitHubの正準形（`> [!NOTE]` の次行が本文）へ戻す（`packages/core/src/alerts.ts`）

### 視認性（コードブロック・見出し）

- **コードブロックの配色は `globals.css` のCSS変数1か所**（`--code-fg` / `--code-keyword` など、
  GitHubのlight/dark配色）で決めている。エディタのCodeMirrorと、埋め込み内の閲覧描画で使う
  highlight.jsが同じ変数を参照するので、どちらもテーマ切り替えに揃って追従する。
  - Crepeの既定は One Dark（暗色前提）で、ライト背景に載ると本文が `#abb2bf` になり
    コントラスト比が2:1を切って読めなかった → `Crepe.Feature.CodeMirror` の `theme` を差し替え
    （`apps/web/lib/codeTheme.ts`）。色は直値ではなく `var(--code-*)` を参照しているので、
    エディタを作り直さなくてもテーマ切り替えに追従する
  - Tailwind typographyの `pre` は暗い背景前提の薄い文字色を当てるため上書き。
    言語指定なしのコードブロック（hljsクラスが付かない）も必ず読める色になる
  - **選択範囲の色は `!important` で上書きしている**。CodeMirrorの基本テーマが
    `&dark.cm-focused > .cm-scroller > .cm-selectionLayer .cm-selectionBackground`（#233）という
    こちらより高い詳細度で当ててくるため、そのままだと選択部分が黒く潰れて読めない。
    ここはCSS変数1本でライト/ダーク両方を賄う方針なので、明示的に勝たせている
- **見出しはサイズ差だけに頼らない**。レベルごとに装飾の種類を変える:
  h1=太い下罫線 / h2=細い下罫線 / h3=左縦バー＋アクセント色 / h4=アクセント色 /
  h5=弱色＋`▸` / h6=弱色＋`•`＋小文字大文字化。日本語だと `text-transform` が効かないため、
  h5・h6には先頭記号を付けて大きさ以外の差を作っている
- エディタと閲覧描画で同じ見出しスタイルを使う（`.docvault-editor` スコープを1段かぶせて
  Crepeの `.milkdown .ProseMirror h1` を上書きしている。Crepeのstyle.cssは動的importで
  後から読み込まれるため、同じ詳細度では勝てない）

### 目次（TOC）の作り

見出しの並びは本文Markdownから取り（`packages/core/src/headings.ts`、フェンス内・引用内は除外）、
ジャンプ先は「描画されたトップレベル見出し要素のN番目」で解決しています。
ProseMirrorの見出しにはid属性が付かないので、**slug生成の一致を気にしなくて済む** のが利点です。

### WYSIWYGエディタの選定
**Milkdown Crepe（ProseMirror系）を採用。** Milkdownは内部表現がremark ASTで、
パースとシリアライズが対称なため「Markdownが実体」という本アプリの前提に最も適合します
（TipTapはHTML/独自JSONが実体でMarkdownは変換層になる）。実装上の注意点は2つ:

1. remark-stringifyがテキスト中の `[` を `\[` にエスケープするため、
   `> [!NOTE]` / `![[...]]` / `[^1]` が保存時に壊れる → 保存前に正規化して戻す
   （`apps/web/lib/crepeMarkdown.ts`）
2. 初期化直後にも正規化済みMarkdownで `markdownUpdated` が発火する →
   ユーザーが実際に操作するまで変更を伝播しない（開いただけでコミットが走らない）

### 埋め込みブロックの書き戻し
ブロック特定はObsidian互換の**行末 `^block-id` マーカー**（`packages/core/src/blocks.ts`）。
ブロック＝マーカー行を含む空行区切りの連続行として抽出・置換し、マーカーは書き戻し後も維持します。
書き戻しは「元ファイルの内容置換 → 通常の保存フロー」に乗せるため、
元ファイルがリモートで先に更新されていた場合も**通常の競合検知（ref/SHAベース）がそのまま働きます**。

### パーサー/シリアライザ構成（編集⇔保存の往復）
- 保存形態: 常にプレーンGFM（+ Alerts / Mermaid / `![[...]]` / `^id` はすべてGFMとして無害なテキスト）
- 編集時: Crepe（remark）。Mermaid・Alerts・埋め込みは**コードブロック/引用/テキストのまま保持**され、往復で壊れない。
  見せ方だけをDecorationで切り替えるので、ドキュメントの中身は触っていない
- 閲覧描画（埋め込みの参照表示）: フェンス考慮の行単位セグメント分割（`packages/core/src/segments.ts`）で
  Mermaid / Alerts / 埋め込みを専用コンポーネントへ、残りを react-markdown
  （remark-gfm + remark-gemoji + rehype-highlight + rehype-slug）で描画

### ファイル移動・リネームUI
移動ダイアログ（必須要件）に加えて、ツリー上の**ドラッグ&ドロップ移動**、
ページ上部のタイトル欄／ツリーの鉛筆アイコン・ダブルクリックからの**リネーム**を実装しています。
すべて同じ `moveDoc` に集約され、リンク書き換え＋1コミットで反映されます
（同一フォルダ内の名前変更だけの場合は `docs: rename ...` としてコミット）。

### Drawio等の自由作図
スコープ外（Mermaidを基本とする）。将来 `.drawio.svg` を画像として扱う拡張は
現在の `_assets/` 設計と互換です。

## テスト

- `packages/core`: vitestユニットテスト55件（リンク書き換え・パス解決・ブロック置換・
  frontmatter・ドキュメント名/リネームパス・Alertsの正規化とセグメント分割・
  目次用の見出し抽出・未参照画像検出）
- E2E: GitHub REST APIをインメモリモックしたPlaywrightスモークテストで、
  PAT入力 → 共有リンク到達 → ライブエディタ（Mermaid/Alerts/埋め込みのライブ描画と
  カーソルによるソース切り替え）→ 埋め込み書き戻し → DBビュー → 検索 →
  移動・リネーム時のリンク/画像パス書き換え → 未参照画像削除 → テンプレート作成 →
  デバウンスpush までを検証済み

## 既知の制約

- Alertsは色と枠が付くが、マーカー `[!NOTE]` 自体は実体として表示したまま
- 絵文字ショートコード（`:tada:`）とセクションアンカー（`#見出し` へのリンク）は
  閲覧モードが持っていた機能で、ライブエディタでは変換されない
  （どちらもGitHub上では従来どおり描画される）
